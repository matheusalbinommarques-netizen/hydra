# Product Roadmap

## Release 0 — Protótipo da experiência

**Objetivo:** validar se a orientação é compreensível e útil.

Inclui:

- criação simulada de projeto;
- origem;
- contexto;
- problema;
- resultado desejado;
- resumo;
- próxima ação;
- mapa da jornada;
- retorno e edição;
- ação de pular;
- pendência visível.

**Critério de sucesso:** uma pessoa explica onde está, o que fazer, por que fazer e o que vem depois.

## Release 1 — Walking Skeleton

**Objetivo:** provar tecnicamente uma jornada mínima de ponta a ponta.

Fluxo:

```text
Criar projeto
→ registrar problema
→ definir objetivo
→ criar três itens de backlog
→ selecionar entrega
→ concluir uma atividade
→ registrar aprendizado
→ encerrar projeto
```

Inclui:

- aplicação funcional;
- persistência simples;
- importação e exportação JSON;
- navegação;
- motor básico;
- testes automatizados de regras;
- resumo da jornada.

## Release 2 — Alpha orientada

**Objetivo:** permitir que um usuário estruture e planeje a primeira entrega.

Inclui:

- diagnóstico;
- estado atual;
- usuários;
- visão;
- objetivos;
- stakeholders;
- premissas;
- restrições;
- riscos;
- funcionalidades;
- fora do escopo;
- backlog;
- primeira entrega;
- critérios de aceitação;
- DoD.

## Release 3 — MVP

**Objetivo:** integrar concepção, execução, validação e encerramento.

Acrescenta:

- quadro de execução;
- impedimentos — Cockpit/Impedimentos v0 (registrar, classificar, definir próxima ação, resolver, reabrir) antecipado intencionalmente antes de Release 1, por decisão explícita (D022, `docs/07-management/decision-log.md`); o restante desta lista permanece não antecipado;
- decisões;
- mudanças;
- atualização de riscos;
- status;
- review;
- aceite;
- retrospectiva;
- lições;
- encerramento.
